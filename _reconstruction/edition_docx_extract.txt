1. Purpose &amp; rules of this document
This document helps owners decide which features should exist, which are necessary, which belong in which commercial edition, which should be simplified or hidden, which are too complex for small businesses, and which should be reserved for higher editions.
Hard rules for this discovery phase:
• Do NOT change ERP code, database, migrations, UI, or permissions based on this document alone.
• Do NOT delete features or create subscription locks until owners approve a later implementation plan.
• Do NOT invent features that do not exist in the product.
• Do NOT treat recommendations as final decisions — mark OWNER DECISION where unsure.
• Simplified edition ≠ different accounting law. Prefer simpler UI / fewer modules / fewer options.
• Underlying platform should stay architecturally consistent (one data plane, gold_ledger + ULE).
1.1 Design principle (hypothesis only)
Edition 1 (₹10K): SIMPLE / FAST / EASY / ESSENTIAL — still a genuinely useful product.Edition 2 (₹30K): MORE CONTROL / AUTOMATION / BUSINESS FEATURES.Edition 3 (₹50K): COMPLETE ERP — manufacturing depth, portals, advanced accounting/CRM/AI.Do not artificially gut basics only to force upgrades.
1.2 Existing Ornexa plan ladder (reference — not this exercise)
docs/SAAS_ENTITLEMENT_AND_BILLING.md already defines ORNEXA BASIC / GROWTH / PROFESSIONAL / SCALE / MAX with surface + portal + AI entitlements. That ladder is REFERENCE ONLY. This document evaluates a separate commercial shape: ₹10K / ₹30K / ₹50K. Owners must decide how (or whether) the two models converge.
