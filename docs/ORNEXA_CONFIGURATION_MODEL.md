# Ornexa Configuration Model

## Configuration Hierarchy

Platform -> plan -> tenant -> branch -> role/user.

## Configurable Areas

Modules, transaction definitions, fields, formulas, workflows, approvals, numbering, documents, reports, notifications, rates, QC, roles, permissions, AI, hardware, storage, security, integrations, tax, payment modes, labour, holidays, page columns, barcode/tag formats, and portals.

## Change Rules

Configuration changes are business policy changes. Validate dependencies, show affected modules, save a new version with effective date, actor, reason, approval, old/new values, and apply to future transactions unless explicitly migrated.
